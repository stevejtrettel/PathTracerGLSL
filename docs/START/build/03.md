# Phase 3: First Hit (Minimal)

## Goals and Purpose

Phase 3 introduces spatial intersection - the ability to find where rays hit objects in 3D space. We're implementing the Scene module, which knows about the geometry in our world and can answer the fundamental question: "where does this ray first hit something?" We're using Signed Distance Fields (SDFs) and ray marching, establishing the mathematical approach that will carry through our entire renderer.

The key insight being tested is that we can represent complex geometry implicitly through distance functions rather than explicit triangles. The sphere we're rendering is defined by a single equation - "distance from center minus radius" - yet we can find precise intersections with it through iterative marching. This phase proves our SDF infrastructure works and can produce accurate surface information.

## What We're Building

### Scene Module Architecture

**Scene Module** owns all knowledge about what exists in 3D space. For Phase 3, this is just a single sphere, but the architecture we're establishing will eventually support complex scenes with multiple objects and materials. The Scene module provides two critical pieces of information: WHERE surfaces exist (through intersection) and HOW they're oriented (through normals).

**Ray Marching Algorithm** is our method for finding intersections with implicit surfaces. Instead of solving ray-surface equations analytically, we march along the ray in steps sized by the distance to the nearest surface. This elegant algorithm works for any shape we can express as a distance function, from simple spheres to complex fractals.

**Hit Structure** captures the essential information about a ray-surface intersection. In Phase 3, we keep it minimal - just position, normal, and distance along ray. This structure will grow as we add materials and lighting, but we start with the geometric essentials.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Implicit Surface Representation** - Geometry defined by distance functions, not meshes
2. **Iterative Intersection** - Finding surfaces through marching, not analytical solutions
3. **Normal Computation** - Deriving surface orientation from the SDF gradient
4. **Scene Owns Geometry** - All spatial queries go through the Scene module

### What Changes After Phase 3

Before Phase 3: We can generate rays but they don't hit anything - just infinite empty space.

After Phase 3:
- Rays can find surface intersections through marching
- We can compute surface normals at hit points
- A sphere appears on screen, shaded by its normal directions
- The foundation for complex SDF scenes is in place

The sphere shaded by normals (appearing as a colorful ball) proves our intersection algorithm works correctly and can extract accurate geometric information from implicit surfaces.

The Scene module introduces the SDF approach. The sphere SDF is beautifully simple - just the distance from center minus radius. Ray marching uses this distance to take safe steps, guaranteeing we won't miss the surface. The normal computation exploits the fact that the gradient of a distance field points perpendicular to the surface.

### Hit Structure Definition

```glsl
struct Hit {
  Point p;        // World space position of intersection
  vec3 n;         // Surface normal at intersection
  float t;        // Distance along ray to intersection
}
```

This minimal Hit structure captures just the geometric essentials. We're not tracking materials, texture coordinates, or any other information yet - just where we hit and which way the surface faces.

### Ray Marching Algorithm

```glsl
bool scene_intersect(Ray ray, out Hit hit) {
  float t = 0.0;
  
  for (int step = 0; step < MAX_STEPS; step++) {
    // Current position along ray
    Point p = geometry_geodesic(ray.origin, ray.direction, t);
    
    // Distance to nearest surface
    float d = sphere_sdf(p);
    
    // Hit detection
    if (d < EPSILON) {
      hit.p = p;
      hit.n = compute_normal(p);
      hit.t = t;
      return true;
    }
    
    // March forward by distance (safe step)
    t += d;
    
    // Escaped to infinity
    if (t > MAX_DIST) {
      return false;
    }
  }
  
  return false;  // Ran out of steps
}
```

Ray marching's elegance lies in using the distance function itself to determine step size. We can step forward by the SDF value knowing we won't penetrate any surface closer than that distance. This makes the algorithm both robust and efficient.

### Normal Computation via Gradient

```glsl
vec3 compute_normal(Point p) {
  vec2 e = vec2(EPSILON, 0.0);
  
  // Estimate gradient using finite differences
  vec3 n = vec3(
    sphere_sdf(p + e.xyy) - sphere_sdf(p - e.xyy),
    sphere_sdf(p + e.yxy) - sphere_sdf(p - e.yxy),
    sphere_sdf(p + e.yyx) - sphere_sdf(p - e.yyx)
  );
  
  return normalize(n);
}
```

The gradient of a distance field is perpendicular to the level sets (surfaces). By sampling the SDF at small offsets, we can estimate this gradient numerically, giving us the surface normal. This works for any SDF, no matter how complex.

### Main Shader Integration

```glsl
void main() {
  vec2 pixel = gl_FragCoord.xy;
  vec2 xi = next_2d();
  
  Ray ray = camera_generateRay(pixel, xi);
  
  Hit hit;
  if (scene_intersect(ray, hit)) {
    // Visualize normal as color
    vec3 color = hit.n * 0.5 + 0.5;  // Map [-1,1] to [0,1]
    gl_FragColor = vec4(color, 1.0);
  } else {
    // Background color for rays that miss
    gl_FragColor = vec4(0.0, 0.0, 0.0, 1.0);
  }
}
```

This visualization maps surface normals to RGB colors. The sphere will appear with colors that vary smoothly across its surface - red/green/blue corresponding to X/Y/Z components of the normal. This creates a distinctive "normal ball" appearance that immediately shows if our intersection and normal computation are correct.
