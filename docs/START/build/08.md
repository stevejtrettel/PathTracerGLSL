# Phase 8: Progressive Accumulation

## Goals and Purpose

Phase 8 transforms our renderer from producing single images to progressively refining them over time. We're implementing temporal accumulation - the process of averaging many samples to reduce noise and converge toward the correct image. This is fundamental to Monte Carlo rendering, where each sample contains random error but the average of many samples converges to the true solution.

The critical test here is the accumulation mathematics: correctly averaging new samples with history, maintaining numerical stability over hundreds of frames, and watching noise gradually disappear as variance decreases with the square root of sample count. This phase proves our Film module can maintain temporal coherence and that our random sampling actually improves the image over time.

## What We're Building

### The Accumulation System

**Render Loop** transforms our one-shot renderer into a progressive system that continuously improves image quality. Instead of rendering once and stopping, we render frame after frame, each adding one more sample to the accumulation. The render loop manages timing, sample counting, and the decision of when we have enough samples.

**Sample Counter** tracks how many samples have been accumulated at each pixel. This count is crucial for correct averaging - the weight of each new sample is 1/(n+1) where n is the current count. The counter must be managed carefully, resetting when parameters change and incrementing steadily during accumulation.

**Running Average Algorithm** implements mathematically correct accumulation using the formula `result = old * (n/(n+1)) + new * (1/(n+1))`, which can be more elegantly written as `mix(old, new, 1/(n+1))`. This incremental average is numerically stable and maintains equal weighting of all samples regardless of when they were taken.

**Noise Reduction Through Averaging** demonstrates the fundamental principle of Monte Carlo integration - random errors cancel out through averaging. The shadows that start noisy (each pixel randomly hits or misses the light) become smooth as the random variations average together. The variance decreases as 1/n, so the standard deviation (visible noise) decreases as 1/√n.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Temporal Coherence** - Film maintains state across frames
2. **Incremental Refinement** - Each frame improves the image
3. **Numerical Stability** - Averaging remains accurate over many samples
4. **Sample Independence** - Each sample is unbiased and independent

## Implementation Sketch

### Enhanced MinimalApp with Render Loop

```typescript
class MinimalApp {
  private engine: Engine;
  private parameterStore: ParameterStore;
  private sampleCount = 0;
  private isRunning = false;
  private animationId: number | null = null;
  
  startProgressive(): void {
    // Begin progressive accumulation
    // Reset sample count
    // Start render loop
    
    this.sampleCount = 0;
    this.isRunning = true;
    this.renderLoop();
  }
  
  private renderLoop(): void {
    // Core progressive rendering loop
    // Continues until stopped or converged
    
    if (!this.isRunning) return;
    
    // Update sample count for this frame
    this.engine.setUniform('u_sample_count', this.sampleCount);
    this.engine.setUniform('u_film_reset', false);
    
    // Render one more sample
    this.engine.execute();
    
    // Increment for next frame
    this.sampleCount++;
    
    // Update UI with progress
    this.reportProgress(this.sampleCount);
    
    // Continue accumulating
    this.animationId = requestAnimationFrame(() => this.renderLoop());
  }
  
  stop(): void {
    // Stop progressive rendering
    // Preserve accumulated result
    
    this.isRunning = false;
    if (this.animationId) {
      cancelAnimationFrame(this.animationId);
      this.animationId = null;
    }
  }
  
  private reportProgress(samples: number): void {
    // Show accumulation progress
    // Could update UI, log, or emit events
    
    console.log(`Samples: ${samples}`);
    
    // Estimate variance reduction
    const noiseLevel = 1.0 / Math.sqrt(samples);
    console.log(`Noise level: ${(noiseLevel * 100).toFixed(1)}%`);
  }
}
```

The render loop uses requestAnimationFrame to maintain smooth progressive updates while allowing the browser to remain responsive. Each frame adds exactly one sample, making the accumulation predictable and debuggable.

### Film Module Accumulation (Now Active)

```glsl
Radiance film_accumulate(Spectrum new_sample, vec2 pixel) {
  // This code from Phase 7 now actually runs!
  
  if (u_sample_count == 0 || u_film_reset) {
    // First sample - no history to mix with
    return Radiance(new_sample);
  }
  
  // Read accumulated history
  vec2 uv = pixel / u_resolution;
  Radiance history = texture(u_film_buffer, uv).rgb;
  
  // Compute weight for new sample
  // After n samples, new sample has weight 1/(n+1)
  float n = float(u_sample_count);
  float new_weight = 1.0 / (n + 1.0);
  
  // Running average
  // Equivalent to: history * (n/(n+1)) + new_sample * (1/(n+1))
  return mix(history, Radiance(new_sample), new_weight);
}
```

The accumulation formula is mathematically exact - each sample receives equal weight in the final average. Using mix() is both cleaner and potentially more efficient than explicit multiplication and addition.

### Frame Buffer Management

```typescript
// In Engine
class Engine {
  private framebuffers: {
    current: WebGLFramebuffer;
    previous: WebGLFramebuffer;
    textures: {
      current: WebGLTexture;
      previous: WebGLTexture;
    };
  };
  
  private setupAccumulationBuffers(): void {
    // Create ping-pong buffers for temporal accumulation
    // Current: where we render this frame
    // Previous: accumulated history from last frame
    
    // After each frame, swap current and previous
    // This avoids copying data between buffers
  }
  
  execute(): void {
    // Render with accumulation
    
    // Bind previous frame as input texture
    this.bindTexture('u_film_buffer', this.framebuffers.textures.previous);
    
    // Render to current framebuffer
    this.bindFramebuffer(this.framebuffers.current);
    
    // Draw full-screen quad
    this.drawQuad();
    
    // Swap buffers for next frame
    this.swapBuffers();
    
    // Copy to screen
    this.copyToScreen();
  }
}
```

Ping-pong buffers avoid the cost of copying data. We read from "previous" and write to "current", then swap their roles for the next frame. This pattern is fundamental to temporal effects in real-time rendering.

### Numerical Stability Considerations

```glsl
// Potential precision issues after many samples
Radiance film_accumulate_stable(Spectrum new_sample, vec2 pixel) {
  vec2 uv = pixel / u_resolution;
  Radiance history = texture(u_film_buffer, uv).rgb;
  
  float n = float(u_sample_count);
  
  // For large n, 1/(n+1) becomes very small
  // This can lose precision in the mix
  
  if (n > 1000.0) {
    // Use incremental update for better precision
    // new_avg = old_avg + (new_sample - old_avg) / (n+1)
    Radiance delta = Radiance(new_sample) - history;
    return history + delta / (n + 1.0);
  } else {
    // Standard mix for small n
    return mix(history, Radiance(new_sample), 1.0 / (n + 1.0));
  }
}
```

For high sample counts, the incremental formula maintains better numerical precision by computing the difference first, avoiding the tiny weights that can lose precision in 32-bit floats.
