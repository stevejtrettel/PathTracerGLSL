
# Phase 5 Rendering Architecture
**Parameter-Driven Modular Rendering with Uniform Bindings**

## Core Architecture

```
MinimalApp → ParameterStore → Engine → ShaderCompiler → GPU
```

### Parameter Flow
1. **MinimalApp** sets semantic parameters (`camera.position`, `camera.fov`)
2. **ParameterStore** batches changes and notifies observers
3. **Engine** receives parameter changes and forwards to ShaderCompiler
4. **ShaderCompiler** executes module-declared uniform bindings
5. **GPU** receives properly transformed uniform values

## Key Components

### MinimalApp
- **Responsibility**: Set user-facing parameters only
- **No transformation logic** - just calls `parameterStore.set()` and `parameterStore.batch()`
- **Semantic parameters**: `camera.position: [0,0,10]`, `camera.target: [0,0,0]`, `camera.fov: 60`

### ParameterStore
- **Core operations**: `set()`, `batch()`, `get()`
- **Change notification**: Single `onChange` callback with batched changes
- **Simple storage**: Map of parameter paths to values

### Engine
- **Orchestrates** four subsystems: ModuleRegistry, ShaderCompiler, RenderExecutor
- **Tracks engine state**: frame count, elapsed time, canvas resolution
- **Updates engine uniforms** every frame automatically
- **Forwards parameter changes** to ShaderCompiler

### ShaderCompiler
- **Compiles modules** into complete GLSL fragment shader
- **Manages uniform bindings** declared by modules
- **Updates two types of uniforms**:
    - **Parameter uniforms**: Via module binding system
    - **Engine uniforms**: Direct from Engine each frame

## Uniform Binding System

### Module Declaration
Modules declare how they consume global parameters:

```typescript
const pinholeCamera: ModuleDescriptor = {
  fragment: {
    uniforms: `
      uniform vec3 u_camera_position;
      uniform mat3 u_camera_frame;  
      uniform float u_camera_tan_fov;
    `,
    functions: `...`
  },
  
  uniformBindings: [
    {
      uniform: 'u_camera_position',
      parameters: ['camera.position'], 
      compute: (params) => params['camera.position']
    },
    {
      uniform: 'u_camera_tan_fov',
      parameters: ['camera.fov'],
      compute: (params) => Math.tan(params['camera.fov'] * Math.PI / 180 / 2)
    },
    {
      uniform: 'u_camera_frame',
      parameters: ['camera.position', 'camera.target'],
      compute: (params) => buildFrame(params['camera.position'], params['camera.target'])
    }
  ]
};
```

### Binding Execution
When parameters change:
1. ShaderCompiler finds all bindings that use those parameters
2. Gathers current parameter values for each binding
3. Executes binding's `compute` function
4. Sets resulting uniform value on GPU

## Engine Uniforms

**Automatically provided to all shaders:**
- `uniform vec2 u_resolution` - Canvas dimensions
- `uniform int u_frame_index` - Current frame number
- `uniform float u_time` - Elapsed seconds since start

**Updated every frame** by Engine, no module binding required.

## Key Benefits

### Clean Separation of Concerns
- **App**: User-facing semantics (`camera.fov` in degrees)
- **Modules**: GPU transformation logic (`tan(fov/2)`, frame matrices)
- **Engine**: Automatic engine state management

### Module Self-Containment
Each module declares:
- What uniforms it needs (GLSL)
- What parameters it consumes (bindings)
- How to transform parameters to uniforms (compute functions)

### Extensibility
- **Parameter sharing**: Multiple modules can bind to same parameter
- **Complex transformations**: Multi-parameter → single uniform
- **Generated modules**: WorldCompiler can generate bindings alongside GLSL
