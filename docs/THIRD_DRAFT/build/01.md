# Phase 1: Minimal GPU Triangle

## Goals and Purpose

Phase 1 establishes the foundational Engine architecture that will carry through the entire project. We're building the core systems that validate, compile, and execute modular GLSL code. The visible result will be deliberately minimal - just a red screen - but the infrastructure we're creating is the bedrock everything else will build upon.

The key architectural principle we're establishing is that the Engine knows HOW to orchestrate GPU execution but not WHAT to render. It manages the pipeline of turning modules into running shaders, but the actual rendering logic lives in the modules themselves.

## What We're Building

### Engine Pillar Foundations

We're creating three core components that form the Engine's module system:

**ModuleRegistry** acts as the central repository for all rendering modules. It validates that modules follow our architectural rules, particularly the KIND-based prefixing system where function names must match their module type (camera modules export camera_* functions, etc.). This validation happens at registration time, catching architectural violations before they can cause runtime confusion.

**SimpleCompiler** takes validated modules and concatenates them into a complete GLSL program. At this stage, it's purely concatenation - no transformation or optimization. The compiler's job is to assemble modules in the correct dependency order and add the necessary WebGL boilerplate.

**RenderExecutor** manages the GPU execution pipeline. It owns the WebGL context, manages shader compilation, handles uniforms, and executes draw calls. The executor knows how to run shaders but is agnostic to what they're computing.

### What Changes After Phase 1

Before Phase 1, we have nothing - no rendering capability at all.

After Phase 1, we have:
- A working GPU pipeline that can compile and execute GLSL
- Module validation that enforces our architectural rules
- The ability to render a full-screen quad with any shader we provide
- A foundation ready to accept real rendering modules

The system can now take GLSL code, validate it follows our conventions, compile it, and execute it on the GPU. We're testing this with the simplest possible output - a solid red screen - but the infrastructure is real and complete.

## Implementation Plan

### File Structure Overview

We'll work in three main areas:

1. **Core Engine files** - The registry, compiler, and executor that form the module system
2. **Type definitions** - Interfaces that define the contracts between components
3. **Test harness** - A minimal HTML page and initialization script to verify everything works

### Implementation Order

We'll build in this sequence to maintain testability:

1. **Type definitions first** - Define the ModuleDescriptor interface and related types
2. **ModuleRegistry** - Build validation logic, test with mock modules
3. **SimpleCompiler** - Create concatenation logic, test output manually
4. **RenderExecutor** - WebGL setup and execution
5. **Integration** - Wire everything together with a test module
6. **Test harness** - HTML page that displays our red triangle

This order ensures each component can be tested independently before integration.

  fragment: {

The ModuleDescriptor is our fundamental unit of rendering logic. The `kind` field determines the required prefix for all exported functions, establishing our architectural boundary between module types.

### Test Module (`test/red-module.ts`)

```typescript
const redModule: ModuleDescriptor = {
  id: { kind: 'test', name: 'red', version: '1.0.0' },
  fragment: {
    functions: `
      vec3 test_getColor() {
        return vec3(1.0, 0.0, 0.0);
      }
    `
  },
  exports: ['test_getColor']
};
```

This trivial module serves two purposes: it verifies our architecture works end-to-end, and it's simple enough that any problems must be in our infrastructure, not the rendering logic.

### Integration (`test/phase1.html`)

The test harness initializes all components, registers our test module, compiles it, and executes it:

```javascript
// Create engine components
const registry = new ModuleRegistry();
const compiler = new SimpleCompiler();
const executor = new RenderExecutor(gl);

// Register and compile test module
registry.register(redModule);
const source = compiler.compile([registry.get('test', 'red')]);
executor.loadShader(source);

// Render one frame
executor.execute();
```

## Success Criteria

Phase 1 is complete when:
- The screen shows solid red
- Module validation catches naming violations
- The compiler produces valid GLSL
- WebGL reports no errors
- The architecture is ready for real rendering modules

The red screen itself is unimportant - what matters is that we've established the Engine's architectural patterns and proven the module system works.
