# Phase 12: Material→Light References

## Goals and Purpose

Phase 12 establishes the elegant architectural solution to a complex problem: how do we know which surfaces emit light? Traditional renderers maintain elaborate mappings from objects to lights, tracking which geometry corresponds to which light sources. Our solution is radically simpler - materials directly reference their associated lights through a `light_id` field. When a material emits light, it knows exactly which light it represents, eliminating all the bookkeeping complexity of object-light correspondence.

The critical test here is that emissive materials automatically become lights without explicit object tracking. The WorldCompiler analyzes materials during compilation, creates lights for emissive ones, and assigns the appropriate `light_id` back to each material. When Transport hits a surface, it simply checks if `material.light_id >= 0` to know if it's emissive. No cross-referencing, no lookup tables, no object IDs - just a direct material-to-light reference.

## What We're Building

### The Material-Light Reference System

**Light ID Assignment** happens during compilation when the WorldCompiler examines each material's emission values. Materials with non-zero emission become lights and receive a `light_id` pointing into the light array. Materials without emission get `light_id = -1`, marking them as non-emissive. This assignment happens once at compile time, creating a static but efficient mapping.

**Unified Light Registry** collects lights from all sources into a single array. Explicit lights (like point lights) occupy early positions, followed by lights created from emissive materials. Each light knows its origin - whether it came from an explicit light definition or was derived from an emissive material. The registry maintains indices and metadata but doesn't need complex object mappings.

**Direct Reference Pattern** means materials carry their own light identity. When we query `scene_material_properties()`, the returned structure includes `light_id`, immediately telling us if this material emits light and which light it corresponds to. This direct reference eliminates the traditional need to track which objects are lights, which lights correspond to which objects, and how to map between them.

**Transport Light Detection** becomes trivially simple - after hitting a surface and getting its material properties, Transport just checks `if (props.light_id >= 0)`. If true, this surface emits light and we add its contribution. No searching, no mapping, no object tracking. The material tells us everything we need to know.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Materials Own Their Light Identity** - No separate object-light mapping needed
2. **Compile-Time Light Assignment** - Static analysis creates efficient runtime structure
3. **Unified Light Management** - All lights in one registry regardless of origin
4. **Direct Property Access** - No indirection through object IDs

### Light Registry Structure

```typescript
interface LightRegistry {
  lights: CompiledLight[];           // All lights (explicit + emissive)
  materialLightStart: number;        // Where material-derived lights begin
  
  stats: {
    totalLights: number;
    explicitLights: number;
    emissiveMaterials: number;
  };
}

interface CompiledLight {
  id: string;
  radiance: vec3;
  source: 'explicit' | 'emissive_material';
  
  // For emissive materials
  materialId?: string;
  
  // For explicit lights
  position?: vec3;
  type?: 'point' | 'directional' | 'area';
}
```

The registry unifies all lights while tracking their origins. This enables different handling strategies while maintaining a single light array.

### Enhanced WorldCompiler

```typescript
class WorldCompiler {
  compile(
    scene: SceneDescription,
    lights: LightDescription[],
    geometryModule: ModuleDescriptor
  ): CompiledWorld {
    // Build unified light registry
    const lightRegistry = this.buildLightRegistry(scene, lights);
    
    // Assign light IDs to materials
    const materialsWithLightIds = this.assignLightIds(
      scene.materials,
      lightRegistry
    );
    
    // Generate modules with light references
    const sceneModule = this.compileSceneWithLights(
      scene.objects,
      materialsWithLightIds
    );
    
    const lightingModule = this.compileLightingFromRegistry(
      lightRegistry
    );
    
    return {
      modules: {
        geometry: new PassthroughCompiler(geometryModule).compile(),
        scene: sceneModule,
        lighting: lightingModule
      },
      registry: lightRegistry,
      metadata: {
        objectCount: scene.objects.length,
        materialCount: materialsWithLightIds.length,
        lightCount: lightRegistry.lights.length
      }
    };
  }
  
  private buildLightRegistry(
    scene: SceneDescription,
    explicitLights: LightDescription[]
  ): LightRegistry {
    const registry: LightRegistry = {
      lights: [],
      materialLightStart: 0,
      stats: {
        totalLights: 0,
        explicitLights: 0,
        emissiveMaterials: 0
      }
    };
    
    // First add explicit lights
    for (const light of explicitLights) {
      registry.lights.push({
        id: light.id || `light_${registry.lights.length}`,
        radiance: light.intensity,
        source: 'explicit',
        position: light.position,
        type: light.type
      });
    }
    
    registry.materialLightStart = registry.lights.length;
    registry.stats.explicitLights = registry.lights.length;
    
    // Then add lights from emissive materials
    for (const material of scene.materials) {
      if (this.isEmissive(material)) {
        registry.lights.push({
          id: `emissive_${material.id}`,
          radiance: material.emission,
          source: 'emissive_material',
          materialId: material.id
        });
        registry.stats.emissiveMaterials++;
      }
    }
    
    registry.stats.totalLights = registry.lights.length;
    return registry;
  }
  
  private assignLightIds(
    materials: MaterialDescription[],
    registry: LightRegistry
  ): MaterialWithLightId[] {
    // Assign light_id to each material
    
    return materials.map(mat => {
      let lightId = -1;  // Default: not emissive
      
      if (this.isEmissive(mat)) {
        // Find this material's light in the registry
        const lightIndex = registry.lights.findIndex(
          light => light.materialId === mat.id
        );
        
        if (lightIndex >= 0) {
          lightId = lightIndex;
        }
      }
      
      return {
        ...mat,
        light_id: lightId  // Direct reference to light array
      };
    });
  }
  
  private isEmissive(material: MaterialDescription): boolean {
    // Check if material emits light
    return material.emission.some(e => e > 0);
  }
}
```

The WorldCompiler orchestrates the crucial light_id assignment. It analyzes materials, creates lights for emissive ones, and ensures each material knows its light identity.

### Scene Module Generation with Light IDs

```typescript
// In SceneCompiler
private generateMaterialProperties(materials: MaterialWithLightId[]): string {
  // Generate material property arrays including light_id
  
  const albedoArray = materials.map(m => 
    `vec3(${m.albedo})`
  ).join(', ');
  
  const emissionArray = materials.map(m => 
    `vec3(${m.emission})`
  ).join(', ');
  
  const lightIdArray = materials.map(m => 
    m.light_id
  ).join(', ');
  
  return `
    const vec3 material_albedo[${materials.length}] = vec3[](${albedoArray});
    const vec3 material_emission[${materials.length}] = vec3[](${emissionArray});
    const int material_light_id[${materials.length}] = int[](${lightIdArray});
    
    MaterialProperties scene_material_properties(int mat_id, vec3 p) {
      MaterialProperties props;
      props.albedo = material_albedo[mat_id];
      props.emission = material_emission[mat_id];
      props.light_id = material_light_id[mat_id];
      return props;
    }
  `;
}
```

The generated Scene module includes light_id arrays, making the material-light reference available at runtime.

### Lighting Module with Unified Registry

```typescript
// In LightingCompiler
private generateFromRegistry(registry: LightRegistry): string {
  // Generate lighting functions for all lights in registry
  
  if (registry.lights.length === 0) {
    return this.generateNoLights();
  }
  
  // Generate light data array
  const lightArray = registry.lights.map((light, index) => {
    if (light.source === 'explicit' && light.type === 'point') {
      return `LightData(
        vec3(${light.radiance}),
        LIGHT_TYPE_POINT,
        vec3(${light.position}),
        ${index}
      )`;
    } else if (light.source === 'emissive_material') {
      // Emissive materials are area lights (not sampled yet)
      return `LightData(
        vec3(${light.radiance}),
        LIGHT_TYPE_EMISSIVE,
        vec3(0),  // No position (distributed)
        ${index}
      )`;
    }
  }).join(',\n    ');
  
  return `
    const LightData lights[${registry.lights.length}] = LightData[](
      ${lightArray}
    );
    
    LightSample lighting_sample(vec3 p) {
      // For Phase 12: only sample explicit lights
      // Emissive materials discovered through path tracing
      
      // Sample first explicit light (if any)
      if (${registry.materialLightStart} > 0) {
        return sample_light(0, p);  // First explicit light
      }
      
      // No samplable lights
      LightSample ls;
      ls.pdf = 0.0;
      return ls;
    }
  `;
}
```

The Lighting module knows about all lights but for Phase 12 only samples explicit ones. Emissive materials are found through path tracing.
