# Phase 11: WorldCompiler Introduction

## Goals and Purpose

Phase 11 marks a fundamental shift from hand-written modules to generated ones, introducing the WorldCompiler system that transforms high-level scene descriptions into optimized GLSL code. Instead of manually writing Scene and Lighting modules for each configuration, we describe what we want - "a red sphere at origin" or "a point light at (5,5,5)" - and compilers generate the appropriate GLSL implementations. This transformation layer enables rapid experimentation while maintaining the same module interfaces we've established.

The critical test here is that compiled modules behave identically to hand-written ones. The camera shouldn't know or care whether the Scene module was lovingly crafted by hand or generated by compiler - the interface remains the same. This phase proves our module abstraction is solid enough to support both human and machine authorship.

## What We're Building

### The Compilation Pipeline

**SceneCompiler** transforms scene descriptions into Scene modules. Given a list of objects with their SDFs and materials, it generates the complete Scene module with `scene_intersect()`, `scene_material_properties()`, and other required functions. The compiler handles the complexity of combining multiple SDFs, managing material arrays, and optimizing the marching loop. What was hand-written in Phase 3 becomes generated code.

**LightingCompiler** transforms light descriptions into Lighting modules. Given point lights, area lights, or eventually environment maps, it generates the sampling functions, PDF calculations, and data structures needed for illumination. The compiler handles different light types uniformly, generating specialized sampling code for each while maintaining a consistent interface.

**PassthroughCompiler** is our temporary solution for modules we're not ready to generate yet. It takes hand-written code and wraps it in the compiler interface, allowing the WorldCompiler to treat all modules uniformly even when some are still manual. The Geometry module remains hand-written but goes through PassthroughCompiler.

**Scene and Light Descriptions** are the high-level specifications that drive compilation. Instead of writing GLSL, we describe scenes as data structures: objects have positions, shapes, and materials; lights have positions, colors, and intensities. These descriptions are much easier to manipulate programmatically than raw GLSL strings.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Description-Driven Generation** - High-level specs compile to low-level code
2. **Interface Stability** - Generated modules match hand-written interfaces
3. **Compiler Composition** - Multiple compilers work together
4. **Optimization Opportunities** - Compilers can optimize based on scene analysis

### What Changes After Phase 11

Before Phase 11: Every module is hand-written, changes require editing GLSL.

After Phase 11:
- Scenes are described as data, not code
- Adding objects means adding descriptions, not writing SDFs
- Material changes are data edits, not shader modifications
- The same visual result, but from compiled modules
- Foundation for dynamic scene generation

The identical visual output proves our compilation pipeline generates correct modules that maintain established interfaces.

## Implementation Plan

### File Structure Overview

We're adding the compiler infrastructure:

1. **Compiler System**
    - `compilers/scene-compiler.ts` - Generates Scene modules
    - `compilers/lighting-compiler.ts` - Generates Lighting modules
    - `compilers/passthrough-compiler.ts` - Wraps hand-written code
    - `compilers/world-compiler.ts` - Orchestrates compilation

2. **Description Types**
    - `world/types.ts` - Scene and light description interfaces

3. **SDF Library**
    - `world/sdf-library.ts` - Standard SDF functions

### Implementation Order

Building the compilation system incrementally:

1. **Define description types** - Scene and light specifications
2. **Create PassthroughCompiler** - Wrap existing modules
3. **Build SceneCompiler** - Generate Scene from descriptions
4. **Build LightingCompiler** - Generate Lighting from descriptions
5. **Create WorldCompiler** - Orchestrate all compilers
6. **Replace hand-written modules** - Use compiled versions
7. **Verify identical behavior** - Same visual output

This order allows testing each compiler independently.

### Scene Description Types

```typescript
interface SceneDescription {

interface ObjectDescription {
  id: string;
  type: 'sphere' | 'box' | 'plane' | 'sdf';  // Primitives or custom

  };

  albedo: vec3;
  emission: vec3;
  roughness?: number;  // Future
  metallic?: number;   // Future
}
```

Scene descriptions capture the essential information without implementation details. A sphere is just "sphere at position with radius" rather than an SDF function.

### SceneCompiler

```typescript
class SceneCompiler {
  compile(scene: SceneDescription): ModuleDescriptor {
    // Transform scene description into Scene module
    
    const functions = this.generateFunctions(scene);
    const uniforms = this.generateUniforms(scene);
    
    return {
      id: { kind: 'scene', name: 'compiled', version: '1.0.0' },
      fragment: { functions, uniforms },
      exports: ['scene_intersect', 'scene_material_properties', 'scene_intersect_any']
    };
  }
  
  private generateFunctions(scene: SceneDescription): string {
    // Generate all Scene module functions
    
    const sdfFunctions = this.generateSDFs(scene.objects);
    const intersectFunction = this.generateIntersect(scene.objects);
    const materialFunction = this.generateMaterialQuery(scene.materials);
    
    return `
      ${sdfFunctions}
      
      ${intersectFunction}
      
      ${materialFunction}
    `;
  }
  
  private generateSDFs(objects: ObjectDescription[]): string {
    // Generate SDF for each object
    
    return objects.map((obj, index) => {
      if (obj.type === 'sphere') {
        return `
          float sdf_${index}(vec3 p) {
            // Sphere SDF
            vec3 center = vec3(${obj.transform?.position || [0,0,0]});
            float radius = ${obj.parameters?.radius || 1};
            return length(p - center) - radius;
          }
        `;
      }
      // Other primitive types...
      
      if (obj.type === 'sdf' && obj.sdfCode) {
        // Custom SDF provided
        return `
          float sdf_${index}(vec3 p) {
            ${obj.sdfCode}
          }
        `;
      }
    }).join('\n');
  }
  
  private generateIntersect(objects: ObjectDescription[]): string {
    // Generate scene_intersect function
    
    const dispatchSDF = objects.length > 5
      ? this.generateLoopDispatch(objects)
      : this.generateUnrolledDispatch(objects);
    
    return `
      bool scene_intersect(Ray ray, out Hit hit) {
        float t = 0.0;
        
        for (int step = 0; step < MAX_STEPS; step++) {
          vec3 p = ray.origin + ray.direction * t;
          
          ${dispatchSDF}
          
          if (d < EPSILON) {
            hit.p = p;
            hit.n = compute_normal(p);
            hit.t = t;
            hit.material_to = material_id;  // Set by dispatch
            hit.frame = geometry_frame(p, hit.n);
            return true;
          }
          
          t += d * 0.9;
          if (t > MAX_DIST) return false;
        }
        
        return false;
      }
    `;
  }
}
```

SceneCompiler generates the same functions we've been hand-writing but customized for the specific scene. It can optimize based on object count - unrolling for few objects, using loops for many.

### LightingCompiler

```typescript
class LightingCompiler {
  compile(lights: LightDescription[]): ModuleDescriptor {
    // Transform light descriptions into Lighting module
    
    const functions = this.generateFunctions(lights);
    const uniforms = this.generateUniforms(lights);
    
    return {
      id: { kind: 'lighting', name: 'compiled', version: '1.0.0' },
      fragment: { functions, uniforms },
      exports: ['lighting_sample']
    };
  }
  
  private generateFunctions(lights: LightDescription[]): string {
    // Generate lighting functions
    
    if (lights.length === 0) {
      // No lights - return dummy implementation
      return `
        LightSample lighting_sample(vec3 p) {
          LightSample ls;
          ls.radiance = vec3(0.0);
          ls.pdf = 0.0;
          return ls;
        }
      `;
    }
    
    if (lights.length === 1) {
      // Single light - no selection needed
      return this.generateSingleLight(lights[0]);
    }
    
    // Multiple lights - need selection
    return this.generateMultiLight(lights);
  }
  
  private generateSingleLight(light: LightDescription): string {
    // Generate sampling for one light
    
    if (light.type === 'point') {
      return `
        LightSample lighting_sample(vec3 p) {
          vec3 light_pos = vec3(${light.position});
          vec3 light_radiance = vec3(${light.intensity});
          
          LightSample ls;
          ls.position = light_pos;
          ls.wi = normalize(light_pos - p);
          ls.distance = length(light_pos - p);
          ls.radiance = light_radiance / (ls.distance * ls.distance);
          ls.pdf = 1.0;
          
          return ls;
        }
      `;
    }
    // Other light types...
  }
}
```

LightingCompiler generates specialized code for different light configurations. A single point light gets a simple implementation, while multiple lights need selection logic.

### PassthroughCompiler

```typescript
class PassthroughCompiler {
  constructor(private module: ModuleDescriptor) {}
  
  compile(): ModuleDescriptor {
    // Simply return the hand-written module
    // This allows WorldCompiler to treat everything uniformly
    return this.module;
  }
}
```

PassthroughCompiler is trivial but important - it lets us incrementally transition from hand-written to compiled modules.

### WorldCompiler

```typescript
class WorldCompiler {
  compile(
    scene: SceneDescription,
    lights: LightDescription[],
    geometryModule: ModuleDescriptor  // Still hand-written
  ): CompiledWorld {
    // Orchestrate compilation of all World modules
    
    // Use compilers for scene and lighting
    const sceneModule = new SceneCompiler().compile(scene);
    const lightingModule = new LightingCompiler().compile(lights);
    
    // Pass through geometry (not generated yet)
    const geometryPassthrough = new PassthroughCompiler(geometryModule);
    
    return {
      modules: {
        geometry: geometryPassthrough.compile(),
        scene: sceneModule,
        lighting: lightingModule
      },
      
      metadata: {
        objectCount: scene.objects.length,
        materialCount: scene.materials.length,
        lightCount: lights.length
      }
    };
  }
}
```

WorldCompiler orchestrates the compilation process, combining generated and hand-written modules into a complete World configuration.

### Usage Example

```typescript
// Describe the scene as data
const sceneDescription: SceneDescription = {
  objects: [
    {
      id: 'main-sphere',
      type: 'sphere',
      transform: { position: [0, 0, 0] },
      parameters: { radius: 1.0 },
      materialId: 'red-matte'
    }
  ],
  materials: [
    {
      id: 'red-matte',
      albedo: [0.8, 0.2, 0.2],
      emission: [0, 0, 0]  // Not emissive
    }
  ]
};

const lightDescription: LightDescription[] = [
  {
    type: 'point',
    position: [5, 5, 5],
    intensity: [100, 100, 100]
  }
];

// Compile to modules
const worldCompiler = new WorldCompiler();
const world = worldCompiler.compile(
  sceneDescription,
  lightDescription,
  euclideanGeometryModule  // Still hand-written
);

// Use compiled modules exactly like hand-written ones
registry.register(world.modules.scene);
registry.register(world.modules.lighting);
```

1. **Stable Module Interfaces** - Generated modules match hand-written signatures
