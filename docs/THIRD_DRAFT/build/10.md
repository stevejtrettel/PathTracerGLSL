# Phase 10: Reset Logic

## Goals and Purpose

Phase 10 introduces intelligent accumulation management - the system that decides when parameter changes require throwing away accumulated samples and starting fresh. Without reset logic, moving the camera would create ghosting as new views blend with old ones, and changing materials would create impossible transitional states. But resetting too eagerly wastes accumulated samples - adjusting tone mapping shouldn't require restarting accumulation since it only affects display, not the underlying light simulation.

The critical test here is correctly categorizing which parameters affect the rendered content versus just its presentation. Camera position changes the rays we trace, materials change how light bounces, but developer settings only change how we display already-computed radiance values. This phase establishes the decision framework for when accumulated history becomes invalid and must be discarded.

## What We're Building

### The Reset Detection System

**Parameter Metadata** extends our parameter system with semantic information about each parameter's effect on rendering. The `triggersReset` flag explicitly marks whether changing a parameter invalidates accumulated samples. This metadata lives alongside type and range information, creating a complete description of each parameter's role in the system.

**Reset Detection Logic** monitors parameter changes and determines whether they require accumulation reset. Rather than hard-coding these decisions, we use a prefix-based system where entire categories of parameters share reset behavior. This makes the system predictable - all camera parameters trigger reset, all developer parameters don't.

**Film Reset Protocol** coordinates the reset across GPU buffers. When reset is triggered, we set the `u_film_reset` flag telling the Film module to ignore history, reset the sample counter to zero, and clear the accumulation buffers. This ensures the next frame starts fresh without contamination from invalid history.

**Prefix-Based Categorization** groups parameters into reset and no-reset categories using path prefixes. Parameters starting with `camera.` or `material.` require reset because they change what we're rendering. Parameters starting with `developer.` don't require reset because they only change how we display already-rendered content. This pattern scales naturally as we add more parameter categories.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Metadata-Driven Behavior** - Parameters carry semantic information beyond just values
2. **Prefix-Based Policy** - Hierarchical paths enable category-wide rules
3. **Explicit Reset Signaling** - Clear protocol for invalidating accumulation
4. **Conservative Default** - Unknown parameters trigger reset for safety

### What Changes After Phase 10

Before Phase 10: Any parameter change continues accumulating, creating artifacts.

After Phase 10:
- Moving camera immediately shows the new view (no ghosting)
- Changing materials resets and shows correct appearance
- Adjusting gamma doesn't reset (accumulated samples preserved)
- Reset happens automatically based on parameter semantics
- Sample count resets to 1 after parameter changes

The clean reset when moving the camera proves our detection logic correctly identifies when accumulation becomes invalid.

## Implementation Sketch

### Extended Parameter Metadata

```typescript
interface ParameterMetadata {
  type: 'float' | 'vec3' | 'int' | 'bool';
  default: any;
  min?: number;
  max?: number;
  triggersReset?: boolean;  // NEW: Does changing this reset accumulation?
  // Future: group, ui hints, etc.
}

class ParameterStore {
  private parameters = new Map<string, any>();
  private metadata = new Map<string, ParameterMetadata>();
  
  registerMetadata(path: string, meta: ParameterMetadata): void {
    // Store metadata for parameter
    // Set default value if not already set
    // This metadata guides reset decisions
    
    this.metadata.set(path, meta);
    
    if (!this.parameters.has(path) && meta.default !== undefined) {
      this.set(path, meta.default);
    }
  }
  
  getMetadata(path: string): ParameterMetadata | undefined {
    // Retrieve metadata for reset checking
    return this.metadata.get(path);
  }
}
```

The metadata system allows fine-grained control over reset behavior. While we'll mostly use prefix-based rules, specific parameters can override their category's default behavior through explicit metadata.

### Reset Detection in MinimalApp

```typescript
class MinimalApp {
  private parameterStore: ParameterStore;
  private sampleCount = 0;
  private resetPending = false;
  
  // Define reset policies by prefix
  private resetPrefixes = [
    'camera.',      // Camera movement/FOV changes view
    'material.',    // Material changes affect light transport
    'scene.',       // Scene changes affect geometry
    'lights.',      // Light changes affect illumination
  ];
  
  private noResetPrefixes = [
    'developer.',   // Tone mapping doesn't affect sampling
    'debug.',       // Debug visualization doesn't affect sampling
    'ui.',          // UI state doesn't affect rendering
  ];
  
  private setupParameterHandling(): void {
    // Wire parameter changes to reset detection
    
    this.parameterStore.onChange = (changes) => {
      // First, update all uniforms
      this.updateUniforms(changes);
      
      // Then check if any change requires reset
      const needsReset = this.checkNeedsReset(changes);
      
      if (needsReset) {
        this.resetAccumulation();
      }
    };
  }
  
  private checkNeedsReset(changes: ParameterChange[]): boolean {
    // Determine if any parameter change requires reset
    
    for (const change of changes) {
      // First check explicit metadata
      const metadata = this.parameterStore.getMetadata(change.path);
      if (metadata?.triggersReset !== undefined) {
        if (metadata.triggersReset) return true;
        else continue;  // Explicitly doesn't trigger
      }
      
      // Otherwise check prefix-based rules
      if (this.shouldResetForPath(change.path)) {
        return true;
      }
    }
    
    return false;
  }
  
  private shouldResetForPath(path: string): boolean {
    // Apply prefix-based reset policies
    
    // Check no-reset list first (higher priority)
    for (const prefix of this.noResetPrefixes) {
      if (path.startsWith(prefix)) {
        return false;
      }
    }
    
    // Check reset list
    for (const prefix of this.resetPrefixes) {
      if (path.startsWith(prefix)) {
        return true;
      }
    }
    
    // Unknown parameters reset by default (conservative)
    console.warn(`Unknown parameter category: ${path}, assuming reset needed`);
    return true;
  }
  
  private resetAccumulation(): void {
    // Clear accumulation and start fresh
    
    console.log('Resetting accumulation');
    
    // Reset sample counter
    this.sampleCount = 0;
    
    // Signal Film to ignore history
    this.resetPending = true;
    
    // Clear accumulation buffers
    this.engine.clearAccumulationBuffers();
  }
  
  private renderLoop(): void {
    // Progressive rendering with reset handling
    
    if (!this.isRunning) return;
    
    // Pass reset flag to shader
    this.engine.setUniform('u_sample_count', this.sampleCount);
    this.engine.setUniform('u_film_reset', this.resetPending);
    
    // Render frame
    this.engine.execute();
    
    // Clear reset flag after use
    this.resetPending = false;
    
    // Only increment if we didn't reset
    this.sampleCount++;
    
    requestAnimationFrame(() => this.renderLoop());
  }
}
```

The reset detection system uses a two-tier approach: explicit metadata takes precedence, then prefix-based rules apply. This provides both fine-grained control and sensible defaults.

### Film Reset Handling

```glsl
// In Film module
Radiance film_accumulate(Spectrum new_sample, vec2 pixel) {
  // Handle reset signal
  if (u_film_reset || u_sample_count == 0) {
    // Reset requested or first sample
    // Ignore history, start fresh
    return Radiance(new_sample);
  }
  
  // Normal accumulation path
  vec2 uv = pixel / u_resolution;
  Radiance history = texture(u_film_buffer, uv).rgb;
  
  float n = float(u_sample_count);
  return mix(history, Radiance(new_sample), 1.0 / (n + 1.0));
}
```

The Film module checks the reset flag before accumulating. When reset is signaled, it ignores history and returns the new sample directly, starting fresh accumulation.

```typescript
private registerParameters(): void {

  this.parameterStore.registerMetadata('camera.position', {

```

Each parameter registration includes reset behavior. This makes the system self-documenting - you can see which parameters require reset by looking at their metadata.

### Buffer Clearing

```typescript
// In Engine
class Engine {
  clearAccumulationBuffers(): void {
    // Clear to black for fresh start
    
    gl.bindFramebuffer(gl.FRAMEBUFFER, this.framebuffers.current);
    gl.clearColor(0, 0, 0, 0);
    gl.clear(gl.COLOR_BUFFER_BIT);
    
    gl.bindFramebuffer(gl.FRAMEBUFFER, this.framebuffers.previous);
    gl.clearColor(0, 0, 0, 0);
    gl.clear(gl.COLOR_BUFFER_BIT);
  }
}
```
