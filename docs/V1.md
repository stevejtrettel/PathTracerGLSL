# V1 Status & Roadmap

## Overview

Version 1 (V1) of the research path tracer is up and running with a **modular ABI** and a **dumb executor** philosophy:

* **AssemblerLite** turns a handful of shader “modules” (Camera / World / Tracer / Film / Developer) into a single fragment shader (no `#ifdef`s).
* **ShaderProgram** + **Fullscreen** are thin GL wrappers for compiling and drawing a full-screen pass.
* Render flow (non-accumulating v1):
  **Tracer → Film (Passthrough) → Developer (Linear→sRGB) → Screen.**

All of this is validated by **pure TypeScript unit tests** (string assembly) and **one integration example** that renders a lit sphere.

## What Each File Does & How It Fits

### `core/contracts/Descriptors.ts`

**What it does:**
Defines the **ABI** across modules: `ModuleDescriptorBase`, `FilmDescriptor`, `DeveloperDescriptor`, `UniformDecl`, `ProvidedSymbol`, and the reserved **system uniforms** (`g_sys_resolution`, `g_sys_frame`, `g_sys_time`). Includes small validators for `requires` satisfaction.

**Bigger plan fit:**
This is the *stable seam* between **research code** and the **engine**. As we add V2 features (scratch resources, sampler layout, channel registry), these types will expand — but we’ll keep backward compatibility.

**Preliminary?**
Mostly solid, but **preliminary** in two ways:

* No formal notion of **scratch resources** (FBOs/buffers) declared by modules.
* No typed **semantic channels** registry (we hardcode `'radiance'` in comments).

**V2 generalization:**
Add structured declarations for per-pass **inputs/outputs**, scratch buffers (size, format, lifetimes), and a typed **ChannelDescriptor** set. Add **SamplerStream** metadata (names, dimensions).

---

### `engine/shaders/AssemblerLite.ts`

**What it does:**

* Injects a **system prelude** with reserved uniforms.
* Validates `requires` vs `provides`.
* **Prefixes** module uniforms with `g_<module_id>_...`.
* Concatenates GLSL in order and appends **glue** (typically `main()`).

**Bigger plan fit:**
This enforces our “**assemble to one shader, no `#ifdef`s**” policy — keeps research code clean. It’s the core of composability.

**Preliminary?**
Yes. Prefixing is **regex-based** and not yet comment/string-literal safe. No AST. No symbol conflict resolution beyond uniforms.

**V2 generalization:**

* Upgrade to a **tokenizer/mini-parser** for safe renaming.
* Add **name mangling** for functions if needed (or enforce single provider).
* Support **stage pipelines** (vertex/fragment; later compute) and multiple passes.

---

### `engine/shaders/ShaderProgram.ts`

**What it does:**
Tiny WebGL2 wrapper for compile/link/use and uniform location cache.

**Bigger plan fit:**
Used by examples; V2 engine will still need this low-level layer.

**Preliminary?**
Fine for V1. No program interface reflection or uniform setter helpers.

**V2 generalization:**
Add tiny typed **setter helpers** (float, vec2/3/4, mat4, samplerN) and optional program **introspection** caches.

---

### `engine/execution/Fullscreen.ts`

**What it does:**
Draws a fullscreen triangle (VAO setup + draw call).

**Bigger plan fit:**
Foundation for **pass** execution in any pipeline.

**Preliminary?**
Solid as is. No instancing/multiview.

**V2 generalization:**
Not urgent. Keep simple.

---

### `photography/camera/PinholeCamera.ts`

**What it does:**
Provides `generateRay(v_uv)` with aspect-correct pinhole projection and a `cameraToWorld` transform.

**Bigger plan fit:**
Baseline camera ABI. Will coexist with thin-lens/VR/etc.

**Preliminary?**
Good for V1. Lacks **lens sampling**, **aperture**, **focal distance**, rolling shutter, etc.

**V2 generalization:**
Add thin-lens params, lens sampling, sensor model; keep ABI stable.

---

### `world/scene/SDFStub.ts`

**What it does:**
Minimal **analytic sphere** with `intersectScene` + `shadeSurface`. Returns an albedo color; no materials or multiple objects.

**Bigger plan fit:**
A test double for world ABI. Lets tracers develop without a full scene system.

**Preliminary?**
Yes — monolithic and single object; no acceleration, no materials.

**V2 generalization:**
Introduce **Scene/Material** separation:

* `intersectScene` → returns hit record (position, normal, material ID).
* `shadeSurface` → **material system** (Lambert/Mirror/etc.).
* Multiple primitives + simple SDF ops (union, plane, box).

### `photography/tracer/FlatColor.ts`

**What it does:**
`tracePixel` that returns a constant color. Great sanity tracer.

**Bigger plan fit:**
Useful for diagnostics and unit tests.

**Preliminary?**
Intentionally simplistic.

**V2 generalization:**
Keep as-is for tests; no change required.

---

### `photography/tracer/SkyOnly.ts`

**What it does:**
Sky gradient + optional sun lobe; uses camera only (no world).

**Bigger plan fit:**
Provides a miss shader and quick visuals.

**Preliminary?**
Fine for V1. Not physically based.

**V2 generalization:**
Upgrade to **Hosek–Wilkie** or similar model (still optional).

---

### `photography/tracer/OneShot.ts`

**What it does:**
Direct Lambert from a directional sun: camera ray → world hit → albedo \* max(n·L,0) \* sunTint \* sunStrength.

**Bigger plan fit:**
First “real” tracer that exercises camera + world ABIs.

**Preliminary?**
Yes — no **shadows**, no **ambient/sky**, no **materials**, no MIS.

**V2 generalization:**

* Add **shadow ray** (occlusion toward sun).
* Miss → delegate to **SkyOnly** (or a sky module).
* Transition to **sampler layout** (named RNG dimensions) even for one-shot.

---

### `photography/film/Passthrough.ts`

**What it does:**
`film_accumulate(v_uv)` reads `u_traceColor` and outputs semantic channel `'radiance'`.

**Bigger plan fit:**
Matches the ABI we want: **Film owns the semantic channel**, Developer consumes it.

**Preliminary?**
Yes — no accumulation, no variance, no aux buffers.

**V2 generalization:**

* **Running Average Film**: ping-pong RGBA16F and track `frameCount`.
* **Variance/Aux** channels (`albedo`, `normal`) for diagnostics/denoising.
* Formalize **ChannelDescriptor** with formats and lifetimes.

---

### `photography/developer/LinearSRGB.ts`

**What it does:**
`develop(v_uv)` converts `'radiance'` (linear) to sRGB using reserved `g_dev_radiance`.

**Bigger plan fit:**
Defines **developer ABI** (reserved uniform, semantic channel wiring).

**Preliminary?**
Good for V1. No tone mapping beyond linear→sRGB.

**V2 generalization:**
Tone mapping variants (ACES/Fujifilm/Filmic), exposure/gamma controls, debug overlays (heatmaps).

## What’s Preliminary (Summary)

* **AssemblerLite**: regex prefixer; no tokenizer/AST; fragment-only; no multi-pass awareness.
* **Contracts**: no formal **scratch resources**, **channel registry**, or **sampler layout**.
* **World**: single analytic object; no materials/IDs/acceleration.
* **Tracer**: no shadows/MIS/sky fallback; no sample layout.
* **Film**: passthrough only; no accumulation/variance/aux channels.
* **Examples**: pipeline wiring is manual (OK for V1).

## What the Generalized (V2) Versions Should Do

* **Contracts (Descriptors v2)**

    * **Channels**: `outputs: ChannelDescriptor[]` with `name`, `format`, `size semantic`.
    * **Scratch resources**: per-module declared transient buffers/textures with size rules (e.g., viewport, half-res).
    * **Sampler layout**: named RNG dimensions per stage (`pixel`, `path`, `bounce`, `light`, etc.).
    * **Pass descriptors**: optional stages and ordering hints.

* **Assembler (Tokenizer)**

    * Tokenize GLSL to **safely rename** uniforms and optionally functions.
    * Support **multi-stage** assembly (vertex/fragment; future compute).
    * Optional **symbol table** to catch collisions early.

* **Engine (Tiny Pass Graph)**

    * A minimal **Pass** object: shader, input bindings (channels), output bindings (targets), viewport.
    * **Resource allocator**: allocate/reuse textures by (format, size, lifetime).
    * **Channel router**: map film outputs to developer reserved uniforms.
    * Keep executor “dumb”: no scheduling/graph optimizer, just sequential passes.

* **World**

    * Hit record + **material ID**.
    * **Material** modules: `interact()` family (diffuse, mirror).
    * A couple more primitives (plane/box) and trivial BVH if meshes appear (later).

* **Tracer**

    * OneShot+**shadow ray** + sky fallback.
    * Start using **Sampler layout** (deterministic named streams).
    * Maintain ABI symmetry with future path tracer (v2.5).

* **Film**

    * **Running Average** with Ping-Pong (`radiance` stays semantic).
    * Optional **Variance** and **AOVs** (albedo/normal).

* **Developer**

    * **Tone-mapping variants**, debug overlays (variance, albedo, normal), toggles.

## Concrete V2 Plan (step-by-step, small PRs)

### Phase A — Harden the ABI & Assembler (no GL changes)

1. **Descriptors v2**

    * Add `ChannelDescriptor`, `ScratchDescriptor`, and `SamplerLayout`.
    * Keep V1 fields intact for compatibility.

2. **AssemblerLite v2**

    * Implement a **tokenizer** to safely rename uniforms (skip comments/strings).
    * Enforce **reserved names** (e.g., `g_sys_*`, `g_dev_*`) cannot be defined by modules.
    * Add optional **vertex stage** support (still one-pass pipelines in examples).

3. **Tests**

    * New unit tests for channel/scratch validation and tokenizer correctness.

**Outcome:** stronger contracts; same pixels as V1.

---

### Phase B — Minimal Pass System & Channel Router

4. **Engine/Pass.ts** (tiny)

    * A Pass = program + input channel bindings + output target.
    * **Channel Router** maps film outputs → developer inputs (e.g., `radiance` → `g_dev_radiance`).

5. **Engine/ResourcePool.ts**

    * Allocate RGBA16F targets by size; reuse across frames/resizes.
    * Helper: `acquire(format, sizeKey)` / `release(handle)`.

6. **Refactor example** (`pipeline-oneshot-film-dev.ts`)

    * Use Pass objects + Router instead of manual bindings.

**Outcome:** same visible result; infrastructure less manual.

---

### Phase C — Film: Running Average

7. **Film/RunningAverage.ts**

    * `film_accumulate(v_uv)` uses ping-pong RGBA16F and `frameCount`.
    * **Descriptor** declares `'radiance'` output; engine ensures ping-pong scratch resources.

8. **Developer** unchanged.

    * Add tiny example to switch Film: Passthrough ↔ RunningAverage.

**Outcome:** progressive refinement demonstrated (still OneShot tracer).

---

### Phase D — Tracer quality-of-life

9. **OneShot + Shadows**

    * Add a **hard shadow** occlusion test along sun direction.
    * Miss → call sky (or reuse SkyOnly code path).

10. **Sampler layout (v2 minimal)**

* Introduce `SamplerLayout` in Descriptors; implement a **flat deterministic** RNG (pixel + dimension).
* Tracer uses named sample slots even if deterministic (paves way for path tracing v2.5).

**Outcome:** more plausible images, stable sampling ABI.

---

### Phase E — World/Material split

11. **Hit record** (pos/normal/materialID/t).
12. **Material modules** with `interact()` (or your “Interaction” naming).
13. **World** returns hits with material IDs; `shadeSurface` delegates to material logic.
14. Add two materials (Lambert + Mirror) to prove the split.

**Outcome:** architecture closer to the long-term plan; tracers operate on **interactions**, not a monolithic world.

---

## Risk & Guardrails

* **Assembler correctness** is critical → keep **unit tests** exhaustive (renaming, reserved names, requires/provides).
* **Channel routing** must remain **semantic** (no hardcoded texture names in modules).
* **Sampler layout** must be **deterministic** and **named** to avoid correlation bugs later.
* Keep the **engine dumb**: no hidden magic; everything is explicit and testable.

---

## TL;DR

V1 has a clean, working core with a strong ABI and the simplest viable pipeline. The V2 plan **doesn’t break what works** — it **layers**: better contracts (channels/scratch/sampler), a tiny **pass system**, a **running-average film**, **tracer shadows/sky**, and a **world/material** split. Each step is small, testable, and clearly moves us toward the long-term research platform you outlined.
