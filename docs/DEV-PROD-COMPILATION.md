# Development/Production Compilation Split

## Core Principle

**Engine always receives GLSL strings. It never knows about the Compiler or compilation modes.**

```typescript
// Engine's contract - identical in all modes
class Engine {
  loadShaders(shaders: ShaderSource): void {
    // Compile GLSL strings → WebGL programs
  }
}

interface ShaderSource {
  main: { vertex: string; fragment: string };
  display: { vertex: string; fragment: string };
  composite: { vertex: string; fragment: string };
}
```

The **only difference** between development and production is **where these GLSL strings come from**.

---

## Two Modes

### Development Mode (Research)

**Purpose**: Fast iteration during scene development and algorithm research

**Compilation**: Happens **in the browser** on every file save

**Bundle includes**: Compiler code (~500KB)

**Workflow**:
1. Edit `scenes/my-scene.ts` (change material, adjust geometry, etc.)
2. Save file
3. Vite hot-reloads the browser
4. Compiler runs automatically in browser (~1-2 seconds)
5. See updated render

**Command**: `npm run dev`

**Bundle size**: ~500KB (includes Compiler + scene definitions)

---

### Production Mode (Archival)

**Purpose**: Create frozen, optimized version for archival/deployment

**Compilation**: Happens **once at build time** in Node.js

**Bundle includes**: Only static GLSL strings (~50KB)

**Workflow**:
1. Finish research, ready to freeze path tracer
2. Run `npm run build` (once)
3. Compiler runs in Node.js, generates `compiled.ts`
4. Vite builds production bundle (excludes Compiler via tree-shaking)
5. Deploy/archive the frozen version

**Commands**: 
```bash
npm run build         # Compiles shaders + builds bundle
npm run preview       # Test the production build locally
```

**Bundle size**: ~50KB (just Engine + static strings)

---

## Single main.ts Entry Point

```typescript
// main.ts - works in both modes
import { Engine } from './engine/Engine';
import { App } from './app';

// Conditional imports based on mode
const shaders = import.meta.env.MODE === 'development'
  ? await loadShadersFromCompiler()
  : await loadPrecompiledShaders();

// Same Engine API in both modes
const engine = new Engine(canvas);
engine.loadShaders(shaders);

const app = new App(engine);
app.init();

// Development: compile in browser
async function loadShadersFromCompiler() {
  const { Compiler } = await import('./compiler/Compiler');
  const { defineRecipe } = await import('./scenes/my-scene');
  
  console.log('🔧 Development mode: Compiling shaders...');
  const start = performance.now();
  
  const compiler = new Compiler();
  const compiled = compiler.compile(defineRecipe());
  
  console.log(`✅ Compiled in ${Math.round(performance.now() - start)}ms`);
  
  return compiled.variants.get('production')!.shaders;
}

// Production: load static strings
async function loadPrecompiledShaders() {
  const { SHADERS } = await import('./shaders/compiled');
  console.log('🚀 Production mode: Loading precompiled shaders');
  return SHADERS;
}
```

## Build Pipeline

### Development Build

```bash
npm run dev
```

**What happens**:
1. Vite bundles everything (including Compiler)
2. Browser loads and runs the bundle
3. Compiler executes in the browser
4. Hot reload enabled for fast iteration

**No pre-compilation step.** Everything happens at runtime in the browser.

---

### Production Build

```bash
npm run build
```

**What happens**:

**Step 1: Pre-compile shaders (Node.js)**
```typescript
// scripts/compile-shaders.ts
import { Compiler } from '../src/compiler/Compiler';
import { defineRecipe } from '../src/scenes/my-scene';
import fs from 'fs';

console.log('⏳ Pre-compiling shaders...');

const compiler = new Compiler();
const compiled = compiler.compile(defineRecipe());

// Write compiled shaders to source
const output = `// Auto-generated by compile-shaders.ts
// Do not edit manually

export const SHADERS = ${JSON.stringify(compiled.variants.get('production')!.shaders, null, 2)};

export const METADATA = {
  compiledAt: '${new Date().toISOString()}',
  sceneId: '${compiled.sceneId}',
  stats: ${JSON.stringify(compiled.stats)}
};
`;

fs.writeFileSync('./src/shaders/compiled.ts', output);

console.log('✅ Shaders compiled to src/shaders/compiled.ts');
```

This creates:
```typescript
// src/shaders/compiled.ts
export const SHADERS = {
  main: {
    vertex: `#version 300 es
void main() {
  // ... vertex shader code
}`,
    fragment: `#version 300 es
precision highp float;
// ... 5000+ lines of generated fragment shader
`
  },
  display: { /* ... */ },
  composite: { /* ... */ }
};

export const METADATA = {
  compiledAt: '2025-01-17T10:30:00.000Z',
  sceneId: 'cornell-box',
  stats: { total: 1247 }
};
```

**Step 2: Build with Vite**
```bash
vite build
```

Vite's tree-shaking **automatically removes Compiler code** because:
- Production branch never imports `./compiler/Compiler`
- Only imports `./shaders/compiled` (static data)
- Dead code elimination removes unused imports

**Result**: 
- `dist/` folder contains only Engine + static strings
- No Compiler code in production bundle
- Instant load time (no compilation)

## Hot Module Replacement (Development)

In development, Vite's HMR automatically recompiles when scene changes:

```typescript
// main.ts - HMR support
if (import.meta.hot) {
  import.meta.hot.accept('./scenes/my-scene', async () => {
    console.log('🔄 Scene changed, recompiling...');
    
    // Recompile with new scene
    const shaders = await loadShadersFromCompiler();
    engine.loadShaders(shaders);
    engine.reset();  // Reset accumulation
    
    console.log('✅ Reloaded!');
  });
}
```

**What you see**:
1. Edit `scenes/my-scene.ts`
2. Save
3. Console: "🔄 Scene changed, recompiling..."
4. 1-2 seconds later: "✅ Reloaded!"
5. See updated render

**No manual commands needed.**

## Key Decisions Made

### 1. Single main.ts File
**Decision**: One entry point that branches based on `import.meta.env.MODE`

**Rationale**: 
- Simpler than maintaining two separate entry points
- Clear conditional logic at the top
- Easy to understand which code runs when

**Alternative considered**: Separate `main-dev.ts` and `main-prod.ts`
- Rejected: More files to maintain, less obvious

---

### 2. Compiler Bundled in Development
**Decision**: Include full Compiler in development bundle

**Rationale**:
- Enables instant feedback (edit → save → see results)
- No manual build step during research
- Bundle size doesn't matter in development

**Cost**: ~500KB bundle size in dev (acceptable for research workflow)

---

### 3. Tree-Shaking in Production
**Decision**: Rely on Vite's tree-shaking to remove Compiler

**Rationale**:
- Automatic - no manual configuration needed
- Proven technology (standard bundler feature)
- Clean production bundle with zero Compiler code

**Verification**: Check with `npm run build && ls -lh dist/assets/`

---

### 4. Pre-Compile Script
**Decision**: Separate `compile-shaders` script that writes to source

**Rationale**:
- Clear separation: pre-compilation happens before build
- `compiled.ts` can be committed to git (version control)
- Can inspect generated GLSL before building
- Future: Could optionally output separate `.glsl` files

**Alternative considered**: Vite plugin that compiles during build
- Rejected: Less transparent, harder to debug, more magic

---

### 5. Compiled Output Location
**Decision**: Write to `src/shaders/compiled.ts` (source folder)

**Rationale**:
- Can be committed to git
- Can be imported by TypeScript
- Visible in editor (can inspect generated code)
- Treated as source code by Vite

**Alternative considered**: Write to `dist/` or separate output folder
- Rejected: Would need different import path, more complex

---

### 6. Hot Reload Strategy
**Decision**: Full recompilation on scene file changes

**Rationale**:
- Simple: just re-run Compiler with new scene
- Safe: guaranteed fresh compilation
- Fast enough: 1-2 seconds is acceptable

**Alternative considered**: Incremental compilation
- Rejected: Much more complex, small time savings

---

### 7. Engine Stays Mode-Agnostic
**Decision**: Engine never knows about modes or Compiler

**Rationale**:
- Clean separation of concerns
- Engine is simpler (just receives strings)
- Same API in all contexts (dev, prod, tests)
- Can test Engine without Compiler

**This is non-negotiable**: Engine should never import Compiler

## Bundle Size Analysis

### Development Bundle
```
Total: ~500KB (uncompressed)
├── Engine:        ~50KB
├── Compiler:      ~300KB
├── Scene defs:    ~50KB
├── Extensions:    ~50KB
└── Other:         ~50KB
```

**Acceptable because**:
- Only used during research
- Fast iteration more important than bundle size
- Network speed doesn't matter (localhost)

---

### Production Bundle
```
Total: ~50KB (uncompressed)
├── Engine:        ~50KB
├── Static GLSL:   ~5KB (compressed)
├── Extensions:    ~50KB (if needed)
└── Other:         ~20KB

Compiler: 0KB (tree-shaken out)
Scene defs: 0KB (not imported)
```

**Size verification**:
```bash
npm run build
cd dist/assets
ls -lh
# Should see main-[hash].js around 50-100KB
```

### Optional: Export Main Shader as .glsl
For inspection purposes, could also write main shader to separate file:

```typescript

fs.writeFileSync('./dist/shaders/main.frag.glsl', 
  compiled.variants.get('production').shaders.main.fragment
);
```

Then production could load:
```typescript
const mainFragment = await fetch('./shaders/main.frag.glsl').then(r => r.text());
```

**But**: This is optional. Inlining everything works fine.

Could compile all variants (debug, preview, production) and allow switching:

```typescript

export const SHADERS = {
  debug: { /* ... */ },
  preview: { /* ... */ },
  production: { /* ... */ }
};

// main.ts
const variant = new URLSearchParams(window.location.search).get('variant') || 'production';
engine.loadShaders(SHADERS[variant]);
```

**But**: For archival, usually just freeze one variant.

## Common Issues

### Issue: "Compiler is undefined in production"
**Cause**: Importing Compiler in production branch

**Fix**: Only import in development branch:
```typescript
const shaders = import.meta.env.MODE === 'development'
  ? await (async () => {
      const { Compiler } = await import('./compiler/Compiler');  // OK
      // ...
    })()
  : // Don't import Compiler here
```

---

### Issue: "compiled.ts not found"
**Cause**: Forgot to run `npm run compile-shaders` before building

**Fix**: 
```bash
npm run compile-shaders  # Run this first
npm run build            # Then build
```

Or use combined command: `npm run build` (which runs both)

---

### Issue: Hot reload not working
**Cause**: HMR code not in main.ts

**Fix**: Add HMR accept handler:
```typescript
if (import.meta.hot) {
  import.meta.hot.accept('./scenes/my-scene', reloadScene);
}
```

---

### Issue: Production bundle still large
**Cause**: Tree-shaking not working (importing Compiler in prod branch)

**Fix**: Verify conditional imports are correct
```bash
# Should only see Compiler import in dev branch
grep -n "import.*Compiler" src/main.ts
```

## Summary

**Core architecture**:
- Engine always receives GLSL strings (mode-agnostic)
- Development: Compiler runs in browser on every save
- Production: Compiler runs once during build, outputs static files
- Single main.ts with conditional imports based on mode
- Tree-shaking automatically removes Compiler from production

**Commands**:
- `npm run dev` - Fast iteration during research
- `npm run build` - Freeze for archival (run once when done)

**Benefits**:
- Fast development iteration (1-2 second recompile)
- Tiny production bundle (~50KB)
- Clean separation of concerns
- Easy to understand and maintain

**Key insight**: The mode split is purely about **when compilation happens** (browser vs build time), not about different architectures or APIs.
