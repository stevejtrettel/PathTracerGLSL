# Phase 16: Full ResearchApp + Recipes

## Goals and Purpose

Phase 16 transforms our MinimalApp into a full ResearchApp that manages multiple rendering configurations through a recipe system. We're solving a fundamental usability problem: researchers need to quickly switch between different rendering modes - a path tracer for quality, a debug view for understanding problems, a production mode for final outputs - without losing accumulated samples or waiting for recompilation. The recipe system provides instant switching between pre-configured rendering pipelines while maintaining separate accumulation buffers for each.

The critical test here is that recipe switching is instantaneous because all shaders are compiled eagerly at startup, and that each recipe maintains its own film buffers so switching back to a recipe shows the accumulation exactly as you left it. This session persistence transforms the research experience - you can compare different algorithms side by side, quickly check debug visualizations without losing your beauty render, and experiment freely knowing each configuration preserves its state.

## What We're Building

### The Recipe System

**Recipes as Complete Configurations** bundle together all the module selections needed for a particular rendering mode. A recipe isn't just a shader - it's a complete specification of geometry, materials, camera, transport algorithm, film accumulation, and tone mapping. Each recipe represents a different way of looking at the same scene, optimized for different purposes. The path tracer recipe uses full MIS for beautiful images, the debug recipe might show normals or material IDs, and the production recipe could use advanced denoising.

**Eager Compilation at Startup** means we compile all recipe shaders when the app initializes, accepting a few seconds of startup time to enable instant switching later. This transforms the user experience - instead of waiting for compilation every time you switch modes, you pay the cost once upfront. For a typical 2-3 recipe setup, this means 2-3 seconds at startup for hours of fluid experimentation.

**Per-Recipe Resources** ensure each recipe maintains its own accumulation state. When you switch from path tracing to debug mode and back, your accumulated samples are still there. Each recipe has its own film buffers, sample counters, and accumulation state. This persistence means you can freely explore different visualizations without fear of losing work.

**Recipe Bundle Structure** organizes recipes into a cohesive set with a default starting point. The bundle typically contains 2-3 recipes that serve different purposes - not 10 variations of the same algorithm, but fundamentally different ways of visualizing the scene. This focused approach keeps compilation time reasonable while providing the essential modes researchers need.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Configuration as Data** - Recipes are data structures, not code
2. **Eager Resource Allocation** - Everything ready at startup
3. **State Isolation** - Each recipe has independent accumulation
4. **Instant Mode Switching** - Pre-compilation enables fluid workflow

### What Changes After Phase 16

Before Phase 16: Single configuration, mode changes require recompilation.

After Phase 16:
- Multiple rendering modes available instantly
- Each mode preserves its accumulation state
- Switching between modes is instantaneous
- Debug visualization doesn't destroy beauty renders
- Foundation for comparative analysis across algorithms

Being able to switch between a converged path traced image and a debug view instantly, then back to the path traced image with accumulation intact, proves the recipe system successfully manages multiple configurations with independent state.

### RecipeManager

```typescript
class RecipeManager {
  private compiledPrograms = new Map<string, WebGLProgram>();
  private recipeResources = new Map<string, RecipeResources>();
  private activeRecipeId: string | null = null;
  
  constructor(
    private engine: Engine,
    private registry: ModuleRegistry
  ) {}
  
  async compileBundle(bundle: RecipeBundle): Promise<void> {
    // Eagerly compile all recipes at startup
    
    console.log(`Compiling ${Object.keys(bundle.recipes).length} recipes...`);
    const startTime = performance.now();
    
    for (const [id, recipe] of Object.entries(bundle.recipes)) {
      await this.compileRecipe(id, recipe);
    }
    
    const elapsed = performance.now() - startTime;
    console.log(`All recipes compiled in ${elapsed.toFixed(0)}ms`);
  }
  
  private async compileRecipe(id: string, recipe: Recipe): Promise<void> {
    // Compile one recipe and allocate its resources
    
    console.log(`Compiling recipe: ${recipe.name}`);
    
    // Gather modules
    const modules = this.gatherModules(recipe);
    
    // Compile shader program
    const source = this.concatenateModules(modules);
    const program = this.engine.compileProgram(source);
    
    this.compiledPrograms.set(id, program);
    
    // Allocate per-recipe resources
    const resources = this.allocateResources(recipe);
    this.recipeResources.set(id, resources);
  }
  
  private allocateResources(recipe: Recipe): RecipeResources {
    // Create film buffers for this recipe
    
    return {
      filmBuffers: {
        current: this.engine.createFramebuffer(),
        previous: this.engine.createFramebuffer(),
      },
      accumulator: {
        sampleCount: 0,
        lastResetTime: 0
      },
      parameters: new Map(Object.entries(recipe.parameters || {}))
    };
  }
  
  switchToRecipe(id: string): void {
    // Instant switch to pre-compiled recipe
    
    if (!this.compiledPrograms.has(id)) {
      throw new Error(`Recipe ${id} not compiled`);
    }
    
    // Save current recipe state if switching away
    if (this.activeRecipeId) {
      this.saveRecipeState(this.activeRecipeId);
    }
    
    // Switch to new recipe
    const program = this.compiledPrograms.get(id)!;
    const resources = this.recipeResources.get(id)!;
    
    this.engine.useProgram(program);
    this.engine.bindFramebuffers(resources.filmBuffers);
    
    // Restore accumulation state
    this.engine.setUniform('u_sample_count', resources.accumulator.sampleCount);
    
    // Apply recipe parameters
    for (const [param, value] of resources.parameters) {
      this.engine.setUniform(param, value);
    }
    
    this.activeRecipeId = id;
    
    console.log(`Switched to recipe: ${id}`);
  }
  
  private saveRecipeState(id: string): void {
    // Preserve current accumulation state
    
    const resources = this.recipeResources.get(id)!;
    
    // Current sample count already tracked in resources
    // Film buffers automatically preserved (separate per recipe)
    
    console.log(`Saved state for recipe ${id}: ${resources.accumulator.sampleCount} samples`);
  }
}
```

RecipeManager handles compilation and switching, maintaining separate state for each recipe.

### ResearchApp

```typescript
class ResearchApp {
  private engine: Engine;
  private parameterStore: ParameterStore;
  private renderCoordinator: RenderCoordinator;
  private recipeManager: RecipeManager;
  private registry: ModuleRegistry;
  
  // Current state
  private currentRecipeId: string;
  private bundle: RecipeBundle;
  
  constructor(
    canvas: HTMLCanvasElement,
    bundle: RecipeBundle
  ) {
    // Initialize core systems
    this.engine = new Engine(canvas.getContext('webgl2')!);
    this.registry = new ModuleRegistry();
    this.parameterStore = new ParameterStore();
    this.renderCoordinator = new RenderCoordinator(this.engine);
    this.recipeManager = new RecipeManager(this.engine, this.registry);
    
    this.bundle = bundle;
    
    // Load all modules
    this.loadModules();
    
    // Compile all recipes eagerly
    this.initialize();
  }
  
  private async initialize(): Promise<void> {
    // Eager compilation of all recipes
    
    console.log('Initializing ResearchApp...');
    
    // Register standard modules
    this.registerCoreModules();
    
    // Compile all recipes (2-3 seconds for 3 recipes)
    await this.recipeManager.compileBundle(this.bundle);
    
    // Start with default recipe
    this.currentRecipeId = this.bundle.defaultRecipe;
    this.recipeManager.switchToRecipe(this.currentRecipeId);
    
    // Wire up parameter flow
    this.setupParameterFlow();
    
    console.log('ResearchApp ready');
  }
  
  switchRecipe(recipeId: string): void {
    // Instant switch with state preservation
    
    if (!this.bundle.recipes[recipeId]) {
      throw new Error(`Unknown recipe: ${recipeId}`);
    }
    
    // Stop rendering during switch
    const wasRunning = this.renderCoordinator.isRunning();
    if (wasRunning) {
      this.renderCoordinator.stop();
    }
    
    // Switch recipes (instant - already compiled)
    this.recipeManager.switchToRecipe(recipeId);
    this.currentRecipeId = recipeId;
    
    // Update parameters for new recipe
    const recipe = this.bundle.recipes[recipeId];
    if (recipe.parameters) {
      this.parameterStore.batch(recipe.parameters);
    }
    
    // Resume rendering if was running
    if (wasRunning) {
      const mode = recipe.config?.renderMode || 'progressive';
      this.renderCoordinator.setMode(mode);
      this.renderCoordinator.start();
    }
    
    console.log(`Switched to recipe: ${recipe.name}`);
  }
  
  getCurrentRecipe(): Recipe {
    return this.bundle.recipes[this.currentRecipeId];
  }
  
  getAvailableRecipes(): Recipe[] {
    return Object.values(this.bundle.recipes);
  }
}
```

ResearchApp orchestrates the complete system with multi-recipe support.
