# Phase 14: RenderCoordinator

## Goals and Purpose

Phase 14 introduces the RenderCoordinator, extracting rendering execution from the app layer into a dedicated orchestration component. We're solving a growing complexity problem: MinimalApp has been accumulating responsibilities - managing parameters, handling resets, running render loops, tracking progress. By extracting execution management into RenderCoordinator, we create a clean separation between application orchestration (MinimalApp) and rendering execution (RenderCoordinator).

The critical test here is supporting three fundamentally different rendering modes with a unified interface. Interactive mode prioritizes responsiveness for camera movement, progressive mode accumulates samples for quality, and production mode tiles high-resolution images. Each mode has distinct execution patterns, progress tracking, and termination conditions, yet they all share the same underlying rendering pipeline. The RenderCoordinator abstracts these differences, providing a simple start/stop interface while managing the complex mode-specific execution internally.

## What We're Building

### The Execution Management System

**RenderCoordinator** becomes the central authority for rendering execution. It owns the render loop, decides when to reset accumulation, tracks progress, and manages mode transitions. The coordinator knows HOW to execute rendering in different modes but delegates the actual rendering to the Engine. This separation means the Engine focuses on GPU operations while the coordinator handles orchestration and timing.

**Three Execution Modes** each optimize for different use cases. Interactive mode maintains 60fps for smooth camera movement, sacrificing quality for responsiveness. Progressive mode continuously accumulates samples, building quality over time. Production mode renders tiles at maximum quality, supporting resolutions beyond GPU memory limits. The coordinator implements the appropriate execution strategy for each mode.

**Unified Reset Logic** moves from MinimalApp to RenderCoordinator, centralizing the decision of when parameter changes require accumulation reset. The coordinator maintains the prefix-based rules we established in Phase 10 but now owns them directly. This consolidation means reset logic lives in one place rather than being scattered between components.

**Progress Reporting** provides feedback about rendering state through callbacks. Different modes report different metrics - interactive mode reports frame rate, progressive reports sample count, production reports tile completion. The unified callback interface lets consumers handle progress updates appropriately without knowing implementation details.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Mode-Specific Execution** - Different strategies for different use cases
2. **Execution vs Orchestration** - RenderCoordinator executes, App orchestrates
3. **Unified Progress Interface** - Common callback for different progress types
4. **Centralized Reset Authority** - One place decides when to reset

### What Changes After Phase 14

Before Phase 14: MinimalApp contains mixed concerns - parameters, rendering, execution.

After Phase 14:
- Clean separation of execution from orchestration
- Easy mode switching with different behaviors
- Standardized progress reporting across modes
- Reset logic consolidated in one location
- MinimalApp becomes simpler and more focused

The ability to switch between modes and see appropriate execution behavior proves the RenderCoordinator successfully abstracts execution complexity.

## Implementation Sketch

### RenderCoordinator Structure

```typescript
class RenderCoordinator {
  private engine: Engine;
  private mode: RenderMode = 'progressive';
  private running = false;
  private animationId?: number;
  
  // Accumulation state
  private accumulator = {
    sampleCount: 0,
    startTime: 0,
    lastFrameTime: 0
  };
  
  // Reset configuration (moved from MinimalApp)
  private resetPrefixes = ['camera.', 'material.', 'scene.', 'lights.'];
  private noResetPrefixes = ['developer.', 'debug.', 'ui.'];
  
  // Progress callback
  public onProgress?: (info: ProgressInfo) => void;
  
  constructor(engine: Engine) {
    this.engine = engine;
  }
  
  setMode(mode: RenderMode): void {
    // Switch execution mode
    // Stop current execution if running
    
    if (this.running) {
      this.stop();
    }
    
    this.mode = mode;
    this.configureForMode(mode);
  }
  
  start(): void {
    // Start rendering in current mode
    
    if (this.running) return;
    
    this.running = true;
    this.accumulator.startTime = performance.now();
    
    // Dispatch to mode-specific implementation
    switch (this.mode) {
      case 'interactive':
        this.startInteractive();
        break;
      case 'progressive':
        this.startProgressive();
        break;
      case 'production':
        this.startProduction();
        break;
    }
  }
  
  stop(): void {
    // Stop rendering
    
    this.running = false;
    
    if (this.animationId) {
      cancelAnimationFrame(this.animationId);
      this.animationId = undefined;
    }
    
    this.reportProgress({ state: 'stopped' });
  }
}
```

The RenderCoordinator encapsulates all execution logic, providing a clean interface for mode management and execution control.

### Mode-Specific Execution

```typescript
// Progressive Mode - Continuous accumulation
private startProgressive(): void {
  const loop = () => {
    if (!this.running || this.mode !== 'progressive') return;
    
    // Update uniforms for this sample
    this.engine.setUniform('u_sample_count', this.accumulator.sampleCount);
    this.engine.setUniform('u_film_reset', false);
    
    // Render one sample
    const frameStart = performance.now();
    this.engine.execute();
    const frameTime = performance.now() - frameStart;
    
    // Update accumulation
    this.accumulator.sampleCount++;
    this.accumulator.lastFrameTime = frameTime;
    
    // Report progress periodically
    if (this.accumulator.sampleCount % 10 === 0) {
      this.reportProgress({
        mode: 'progressive',
        state: 'rendering',
        samples: this.accumulator.sampleCount,
        frameTime,
        totalTime: performance.now() - this.accumulator.startTime,
        samplesPerSecond: 1000 / frameTime
      });
    }
    
    this.animationId = requestAnimationFrame(loop);
  };
  
  this.animationId = requestAnimationFrame(loop);
}

// Interactive Mode - Real-time preview
private startInteractive(): void {
  // Target frame time for 60fps
  const TARGET_FRAME_TIME = 16.67;  // milliseconds
  
  const loop = () => {
    if (!this.running || this.mode !== 'interactive') return;
    
    const frameStart = performance.now();
    
    // No accumulation in interactive mode
    this.engine.setUniform('u_sample_count', 0);
    this.engine.setUniform('u_film_reset', true);
    
    // Render single frame
    this.engine.execute();
    
    const frameTime = performance.now() - frameStart;
    
    // Report FPS instead of samples
    this.reportProgress({
      mode: 'interactive',
      state: 'rendering',
      fps: 1000 / frameTime,
      frameTime,
      targetMet: frameTime <= TARGET_FRAME_TIME
    });
    
    // Adjust quality if needed (future: resolution scaling)
    if (frameTime > TARGET_FRAME_TIME * 1.5) {
      // Could reduce resolution here
      console.warn('Frame time exceeding target');
    }
    
    this.animationId = requestAnimationFrame(loop);
  };
  
  this.animationId = requestAnimationFrame(loop);
}

// Production Mode - Tiled rendering
private startProduction(): void {
  // Simplified for Phase 14 - full tiling comes later
  // For now, just high-quality single frame
  
  const TARGET_SAMPLES = 1000;
  
  const loop = () => {
    if (!this.running || this.mode !== 'production') return;
    
    if (this.accumulator.sampleCount >= TARGET_SAMPLES) {
      this.stop();
      this.reportProgress({
        mode: 'production',
        state: 'complete',
        samples: this.accumulator.sampleCount
      });
      return;
    }
    
    // Render samples in batches for responsiveness
    const BATCH_SIZE = 10;
    
    for (let i = 0; i < BATCH_SIZE && this.accumulator.sampleCount < TARGET_SAMPLES; i++) {
      this.engine.setUniform('u_sample_count', this.accumulator.sampleCount);
      this.engine.setUniform('u_film_reset', false);
      this.engine.execute();
      this.accumulator.sampleCount++;
    }
    
    // Report production progress
    this.reportProgress({
      mode: 'production',
      state: 'rendering',
      samples: this.accumulator.sampleCount,
      targetSamples: TARGET_SAMPLES,
      percentComplete: (this.accumulator.sampleCount / TARGET_SAMPLES) * 100
    });
    
    this.animationId = requestAnimationFrame(loop);
  };
  
  this.animationId = requestAnimationFrame(loop);
}
```

Each mode implements its own execution strategy while sharing the same Engine interface.

### Reset Management

```typescript
// Reset logic consolidated in coordinator
shouldResetForParameter(path: string): boolean {
  // Check no-reset list first (higher priority)
  for (const prefix of this.noResetPrefixes) {
    if (path.startsWith(prefix)) {
      return false;
    }
  }
  
  // Check reset list
  for (const prefix of this.resetPrefixes) {
    if (path.startsWith(prefix)) {
      return true;
    }
  }
  
  // Conservative default
  console.warn(`Unknown parameter: ${path}, assuming reset needed`);
  return true;
}

resetAccumulation(): void {
  // Clear accumulation and signal reset
  
  this.accumulator.sampleCount = 0;
  this.accumulator.startTime = performance.now();
  
  // Signal film to reset on next frame
  this.engine.setUniform('u_film_reset', true);
  
  // Clear buffers
  this.engine.clearAccumulationBuffers();
  
  this.reportProgress({
    state: 'reset',
    reason: 'parameter_change'
  });
}
```

Reset logic moves from MinimalApp to RenderCoordinator, consolidating execution decisions.

```typescript
interface ProgressInfo {
  mode: RenderMode;
  state: 'idle' | 'rendering' | 'stopped' | 'complete' | 'reset';
  
  // Common fields
  timestamp?: number;
  message?: string;
  
  // Progressive mode
  samples?: number;
  samplesPerSecond?: number;
  
  // Interactive mode
  fps?: number;
  targetMet?: boolean;
  
  // Production mode
  percentComplete?: number;
  targetSamples?: number;
  currentTile?: number;
  totalTiles?: number;
  
  // Timing
  frameTime?: number;
  totalTime?: number;
}

private reportProgress(info: Partial<ProgressInfo>): void {
  if (!this.onProgress) return;
  
  const fullInfo: ProgressInfo = {
    mode: this.mode,
    state: 'rendering',
    timestamp: performance.now(),
    ...info
  };
  
  this.onProgress(fullInfo);
}
```

### Simplified MinimalApp

```typescript
class MinimalApp {
  private engine: Engine;
  private parameterStore: ParameterStore;
  private renderCoordinator: RenderCoordinator;
  
  constructor(canvas: HTMLCanvasElement) {
    this.engine = new Engine(canvas.getContext('webgl2')!);
    this.parameterStore = new ParameterStore();
    this.renderCoordinator = new RenderCoordinator(this.engine);
    
    // Wire parameter changes to coordinator
    this.parameterStore.onChange = (changes) => {
      // Update uniforms
      for (const change of changes) {
        this.engine.updateUniform(change.path, change.newValue);
      }
      
      // Let coordinator handle reset decision
      const needsReset = changes.some(
        change => this.renderCoordinator.shouldResetForParameter(change.path)
      );
      
      if (needsReset) {
        this.renderCoordinator.resetAccumulation();
      }
    };
    
    // Wire progress reporting
    this.renderCoordinator.onProgress = (info) => {
      console.log(`[${info.mode}] Samples: ${info.samples}, State: ${info.state}`);
    };
  }
  
  // Delegation methods - much simpler!
  setRenderMode(mode: RenderMode): void {
    this.renderCoordinator.setMode(mode);
  }
  
  startRendering(): void {
    this.renderCoordinator.start();
  }
  
  stopRendering(): void {
    this.renderCoordinator.stop();
  }
}
```

MinimalApp becomes much simpler, delegating execution to RenderCoordinator.
