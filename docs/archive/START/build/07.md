# Phase 7: First Film (Still One-Shot)

## Goals and Purpose

Phase 7 completes the Photography pipeline by introducing Film and Developer modules, establishing the infrastructure for accumulation and tone mapping even though we're not using accumulation yet. This is a crucial architectural step - we're building the complete pipeline from ray generation through to final display, ensuring all the data transformation stages are in place before we add complexity.

The key insight being tested is that rendering should flow through distinct stages: Transport produces linear spectral radiance, Film accumulates samples over time (even if that's just one sample for now), and Developer converts accumulated radiance to displayable RGB. This separation enables us to change accumulation strategies, tone mapping curves, and color grading independently without touching the rest of the renderer.

## What We're Building

### The Complete Photography Pipeline

**Film Module** acts as the temporal accumulator, even though for Phase 7 it's just passing through single samples. The Film receives radiance values from Transport and will eventually average them over many frames, but for now it establishes the interface and data flow. The critical abstraction is that Film doesn't know about rendering algorithms - it just accumulates values over time.

**Developer Module** converts linear radiance values to displayable RGB colors. Even simple gamma correction is important - without it, our physically correct linear values appear too dark on typical displays. The Developer establishes the pattern for all post-processing: tone mapping, color grading, and artistic adjustments that affect appearance but not physical correctness.

**Complete Main Orchestration** wires together all Photography modules in the correct sequence. The main function becomes the readable story of how an image is created: generate ray, trace transport, accumulate in film, develop for display. This orchestration pattern will remain stable even as individual modules become more sophisticated.

### Architectural Patterns Established

This phase establishes several critical patterns:

1. **Linear vs Display Space** - Clear separation between physical and perceptual
2. **Accumulation Interface** - Film receives samples without knowing their origin
3. **Post-Processing Pipeline** - Developer owns all display transformations
4. **Complete Data Flow** - Ray→Radiance→Accumulation→RGB

### What Changes After Phase 7

Before Phase 7: Direct output from Transport to screen, no post-processing.

After Phase 7:
- Complete Photography pipeline in place
- Gamma correction makes the image properly visible
- Film infrastructure ready for accumulation
- Developer infrastructure ready for tone mapping
- Clean separation between rendering and display

The image looks the same as Phase 6 but properly gamma corrected - the shadows won't be crushed black and the midtones will appear more natural. More importantly, the architecture is complete.

## Implementation Sketch

### Type Definitions

```glsl
// Spectral representation (from Transport)
typedef vec3 Spectrum;

// Accumulated radiance (in Film)
typedef vec3 Radiance;

// Final RGB for display (from Developer)
typedef vec3 RGB;
```

These typedefs make the data transformations explicit. Spectrum flows from Transport, becomes Radiance in Film, and finally RGB from Developer. For now they're all vec3, but the semantic distinction is important.

### Film Module (`modules/film/simple.ts`)

```typescript
const simpleFilm: ModuleDescriptor = {
  id: { kind: 'film', name: 'simple', version: '1.0.0' },
  
  fragment: {
    uniforms: `
      uniform int u_sample_count;     // Current sample count
      uniform bool u_film_reset;      // Should reset accumulation
      uniform sampler2D u_film_buffer; // Previous accumulation (for future)
    `,
    
    functions: `
      Radiance film_accumulate(Spectrum new_sample, vec2 pixel) {
        // Accumulate new sample with history
        // For Phase 7: just pass through (no accumulation)
        
        if (u_sample_count == 0 || u_film_reset) {
          // First sample or reset - no history
          return Radiance(new_sample);
        }
        
        // Phase 7: We never get here (u_sample_count always 0)
        // But the infrastructure is in place for Phase 8
        vec2 uv = pixel / u_resolution;
        Radiance history = texture(u_film_buffer, uv).rgb;
        
        // Running average (not used yet)
        float weight = 1.0 / float(u_sample_count + 1);
        return mix(history, Radiance(new_sample), weight);
      }
    `
  },
  
  exports: ['film_accumulate']
};
```

The Film module has the complete accumulation infrastructure even though we're not using it yet. The pattern of checking sample count and reset flag, reading history, and computing weighted averages is all in place, ready for Phase 8 to actually use it.

### Developer Module (`modules/developer/gamma.ts`)

```typescript
const gammaDeveloper: ModuleDescriptor = {
  id: { kind: 'developer', name: 'gamma', version: '1.0.0' },
  
  fragment: {
    uniforms: `
      uniform float u_developer_gamma;  // Usually 2.2
    `,
    
    functions: `
      RGB developer_develop(Radiance radiance) {
        // Convert linear radiance to display RGB
        // Apply gamma correction for proper display
        
        // Ensure non-negative (physical radiance can't be negative)
        vec3 linear = max(vec3(0.0), radiance);
        
        // Apply gamma curve
        vec3 corrected = pow(linear, vec3(1.0 / u_developer_gamma));
        
        // Clamp to display range
        return RGB(clamp(corrected, 0.0, 1.0));
      }
    `
  },
  
  exports: ['developer_develop']
};
```

The Developer module transforms physically linear radiance values to perceptually linear display values. Gamma correction compensates for how displays interpret pixel values - without it, a physically correct 50% gray appears too dark. The 2.2 gamma is standard for sRGB displays.

### Complete Main Orchestration

```glsl
void main() {
  vec2 pixel = gl_FragCoord.xy;
  
  // CAMERA: Generate ray with antialiasing
  vec2 xi = next_2d();
  Ray ray = camera_generateRay(pixel, xi);
  
  // TRANSPORT: Compute radiance along ray
  Spectrum radiance = transport_trace(ray);
  
  // FILM: Accumulate samples (pass-through for now)
  Radiance accumulated = film_accumulate(radiance, pixel);
  
  // DEVELOPER: Convert to display RGB
  RGB color = developer_develop(accumulated);
  
  // OUTPUT: Final pixel color
  gl_FragColor = vec4(color, 1.0);
}
```

The main function now tells the complete story of image formation. Each module has a clear responsibility, and data flows through well-defined transformations. This pattern will remain stable even as individual modules become vastly more complex.

### Sample Count Management

```typescript
// In MinimalApp
class MinimalApp {
  private sampleCount = 0;
  
  render(): void {
    // For Phase 7: always pass 0 (no accumulation)
    this.engine.setUniform('u_sample_count', 0);
    this.engine.setUniform('u_film_reset', false);
    
    // Render one frame
    this.engine.execute();
    
    // Don't increment sampleCount yet (Phase 8)
  }
}
```

We're establishing the sample count infrastructure without using it. The Film module receives u_sample_count = 0, so it always returns the new sample without accumulation. This lets us verify the pipeline works before adding temporal complexity.
